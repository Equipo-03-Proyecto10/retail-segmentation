# Redis ACL fixtures

Lines the CI job loads into both Redis instances to test
`deploy/infra/redis/assemble-acl.sh` and `deploy/infra/check-redis.sh`
(F13-05). They are shaped like the service lines in ADR-0037 and
`docs/datastores/redis-design.md`, but name no real service except `svc_auth`.

| File | User | Shape |
|---|---|---|
| `auth.acl` | `svc_auth` | auth's variant: its own prefixes, `+waitaof`, the transaction commands, and a consumer of `stream:users.v1.access_changed` |
| `fixture_a.acl` | `svc_fixture_a` | a producer of `stream:fixture_a.v1.changed` |
| `fixture_b.acl` | `svc_fixture_b` | a consumer of `stream:fixture_a.v1.changed` |
| `over-broad/fixture_c.acl` | `svc_fixture_c` | `~*`: the check must print a `FAIL` line, so it is not vacuous |
| `invalid/fixture_bad.acl` | `svc_fixture_bad` | an unknown command: `ACL LOAD` refuses the file, and both instances keep their previous users |

`streams/` stands in for `contracts/streams/` (`STREAMS_DIR`). The passwords
are generated by the job at run time; none is committed.
