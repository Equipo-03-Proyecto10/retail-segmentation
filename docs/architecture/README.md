# Architecture

Three views of the delivered system, drawn from the code and the deployment
files rather than from intention. The sources are the originals; the SVGs
beside them are generated by [`render.sh`](render.sh) and are what the delivery
document embeds.

| View | Answers | Built with |
|---|---|---|
| [Application](application.svg) — [source](application.d2) | What the monolith is made of, and what it deliberately is not | d2 |
| [Deployment](deployment.svg) — [source](deployment.d2) | Where the system runs, and what reaches it — rule names, ports, headers | d2 |
| [Infrastructure](infrastructure.svg) — [source](infrastructure.py) | The same topology with vendor icons, for the slide deck | `diagrams` over Graphviz |

**The deployment and infrastructure views overlap on purpose and will drift if
only one is updated.** They exist for different audiences: the deployment view
carries the detail a reader needs to verify a claim (`mosaiq-allow-https`,
`X-Forwarded-For`, `Restart=on-failure`), while the infrastructure view is the
picture that reads from the back of a room. A change to the deployment must
edit both. If that upkeep is not wanted, delete `deployment.d2` and keep the
icons plus the prose below.

## The monolith

The system is **one deployable unit**: a single Flask process under Gunicorn,
supervised by systemd, in front of one PostgreSQL database on the same
instance ([ADR-0001](../adr/0001-flask-monolith-on-a-single-vm.md)). There is no
second service, no internal network call, and no JSON or XML exchanged between
internal components — constraint C-2 in [`../scope.md`](../scope.md). The
browser receives HTML, and every page is rendered server-side with Jinja2.

That is a property worth stating plainly, because it is the thing the second
delivery reverses
([ADR-0016](../adr/0016-the-second-delivery-reinstates-the-distributed-architecture.md)).

## The layers, and how they map onto MVC

Flask is not an MVC framework and does not impose these boundaries; the
layering is the team's, and the directory structure is what enforces it. The
mapping is nonetheless exact:

| Layer | Directory | MVC role | Responsibility |
|---|---|---|---|
| Request preamble | `web/app.py`, `web/middleware/` | — | `ProxyFix` resolves the real client, `web/errors.py` assigns the request id, and the authorization gate refuses by default: a route that declares nothing is refused too ([ADR-0007](../adr/0007-permissions-in-code-with-a-default-deny-middleware.md)) |
| Routes | `web/routes/` | **Controller** | One blueprint per area. Reads the request, calls one service, chooses the template or the redirect. No SQL and no business rule lives here |
| Services | `web/services/` | **Model** — business rules | Where a use case is decided, and where the transaction is opened and committed ([ADR-0014](../adr/0014-service-owned-transactions-and-typed-write-failures.md)). Returns typed failures rather than letting a database error reach a view |
| Data access | `web/db/` | **Model** — persistence | `psycopg`, a module per table area, every statement parameterized. It is the only layer that writes SQL |
| Templates and static | `web/templates/`, `web/static/` | **View** | Jinja2 templates and macros over the design system's tokens and self-hosted IBM Plex |

The dependency direction is one-way — Controller → Model → database, and
Controller → View. A template never reaches the database, and `web/db` knows
nothing about a request.

Two invariants are enforced *below* the application as well as inside it: the
single-administrator rule holds a partial unique index in
[`sql/01_schema.sql`](../../sql/01_schema.sql) as well as an application check,
and the audit trail is written by `fn_audit()` triggers that read the actor the
service set on the connection. Neither can be bypassed by a direct `INSERT`.

## MongoDB and Redis are in the design, not in the system

Both appear in the application view, drawn dashed and greyed, because the
design work is real and belongs to the architecture:
[`../datastores/mongodb-design.md`](../datastores/mongodb-design.md) specifies
six collections for the deferred analytics modules, and
[`../datastores/redis-design.md`](../datastores/redis-design.md) specifies the
key patterns and TTLs for sessions, caching, counters and locks.

Neither runs. No engine is installed, no connection code is written, no
dependency is added and no configuration variable for either exists — the
condition [ADR-0005](../adr/0005-document-mongodb-and-redis-designs-without-implementing-them.md)
attached to committing those designs, and the reason
[`../datastores/README.md`](../datastores/README.md) opens by warning a reader
not to mistake a design for a component. The dashed border carries that warning
into the diagram, and it is why the two do not appear in the deployment view at
all: nothing is deployed.

[ADR-0016](../adr/0016-the-second-delivery-reinstates-the-distributed-architecture.md)
puts both into real operation for the second delivery.

## Regenerating

```sh
sudo pacman -S d2 graphviz         # once; or https://d2lang.com
python -m venv docs/architecture/.venv
docs/architecture/.venv/bin/pip install -r docs/architecture/requirements.txt

./docs/architecture/render.sh      # SVG; --png for slide decks
```

Edit the source, re-run the script, commit the source and the SVG together.
`render.sh` skips the icon diagram with a notice when the virtualenv is absent,
so the d2 views render on a machine that has only d2.

Each source pins its own layout engine, because the two graphs want different
ones: the deployment view is a chain and lays out as a portrait page under
`dagre` (1:1.5), while the application view is a wide layered picture and fits
a slide under `elk` (1:0.33). The `classes` block at the top of each file
carries the MOSAIQ palette from
[`../design-system/tokens/primitives.css`](../design-system/tokens/primitives.css),
so a diagram and a screenshot of the application agree on their colours.

`--png` goes through `rsvg-convert` on purpose: `d2 out.png` downloads and
drives a headless browser on first use, which takes minutes. SVG is native and
renders in about half a second.
