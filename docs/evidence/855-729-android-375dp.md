# #855 and #729: each store profile and the outbox at 375 dp, light and dark

#855 (F27-01) and #729 merged without these screenshots, because no emulator was
available that day. Both stories ask for them as acceptance criteria:

- **#855:** "Given each profile, when evidence is captured, then it shows that
  profile at 375dp in light and dark."
- **#729:** "Given the screen, then it is verified at 375dp in both schemes."

These screenshots come from the real debug app, installed without `-g` and
driven through its own UI on an emulator. It talks to the real services behind
a local gateway, not to fakes, so the refusal on the outbox screens came from
check-ins-service.

## Where it was run

| Piece | Here |
|---|---|
| Emulator | Android Emulator on Windows (WHPX), AVD on `system-images;android-35;google_apis;x86_64`. The display is overridden to 750 × 1334 px at 320 dpi, which is **375 × 667 dp**. |
| App | The debug build of `develop` at `b0cc68c`, with base URL `http://10.0.2.2:8080/` |
| Stack | auth, users, stores and check-ins as local processes, at `develop` `b0cc68c`. They sit behind a stand-in for the gateway on `127.0.0.1:8080`, which routes `/api/<service>/` as `docker/distributed/gateway/default.conf` does. PostgreSQL 18 is loaded from the three scripts. Redis has each service's committed ACL line. These four are the only services the screens below call. |
| Accounts | One seeded account per floor role (F19-04), with the published demonstration password (ADR-0008): `user31` SALES_ASSOCIATE, `user3` STORE_MANAGER, `user32` LOYALTY_OFFICER, `user33` COMMERCIAL_SUPERVISOR, `admin` ADMIN, all `@mosaiq-demo.com` |
| Scheme | `adb shell cmd uimode night no` or `yes`. The app follows the system scheme. |

**To reproduce,** start that stack and install the app, then run this from the
repository root:

```sh
ADB=adb uv run --with pillow python clients/android/evidence/profile_outbox_tour.py docs/evidence
```

[`profile_outbox_tour.py`](../../clients/android/evidence/profile_outbox_tour.py)
sets the 375 dp display and puts it back at the end. It reuses
[`screen_tour.py`](../../clients/android/evidence/screen_tour.py)'s helpers, which
clear the app's data, find each control by its text and tap it. It saves the
`screencap` at full size, 750 × 1334.

## #729: the outbox

The store manager, `user3`, is assigned Store 1 and not Store 2.

| Screenshot (light, dark) | What it shows |
|---|---|
| `729-android-outbox-01-empty-*.png` | Nothing queued: "Everything is synced", with the plain explanation. The tab has no badge. |
| `729-android-outbox-02-refused-and-waiting-*.png` | A check-in at Store 2 was sent online, and check-ins-service refused it with 403 `forbidden_store`. A check-in at Store 1 was then made in airplane mode, so it waits. The summary reads "1 write waiting to send · 1 needs attention", with correct plurals. The refused write says in plain words what happened and what to do, and its technical details are folded under "Details". The tab carries the count of waiting writes. |
| `729-android-outbox-03-details-and-waiting-*.png` | The same, with "Details" opened: the code `forbidden_store` and the correlation id. Below it, the Store 1 check-in reads "Waiting to send". |

At 375 dp no label is truncated and nothing overlaps, in either scheme. The
bottom navigation's four sections fit with their labels, and the refusal text
wraps inside its card. The outbox list scrolls: the waiting Store 1 check-in
sits below the fold in screenshot 02, and 03 shows it.
