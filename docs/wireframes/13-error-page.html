Demo item
—
  1. One template, three messages keyed on the status code. Keeps the masthead so the user is not stranded. A 403 is stated as deliberate — the default-deny middleware refused the route (RF-04), nothing failed.
  2. No stack trace on any of them (RF-15). A failure the user caused explains what to do; one they did not is acknowledged as not their fault.
  3. A 500 shows a reference id that also appears in the server log, so a report can be tied to the logged event. The six admin 404s that used to bypass this handler and lose the id were fixed in #160.

Low-fidelity wireframe. Structure and intent only — the visual design (type, colour, spacing, components) is decided separately in docs/design-system/ and applied in the Jinja2 template. Nothing here is functional.
